# v1.2.3 BuilderKit Correction

## F-000-03 — Windows PowerShell 5.1 empty-array normalization

v1.2.2 could parse a real empty `gh repo list ... --json name` result (`[]`) into a null placeholder under Windows PowerShell 5.1 strict mode, causing `PropertyNotFoundStrict` before any planned repository action. v1.2.3 explicitly normalizes a null `ConvertFrom-Json` result to a true empty array and validates the `name` property through `PSObject.Properties` before access. The Windows contract test captures native output as bytes and uses tolerant explicit decoding so OEM-encoded diagnostics cannot mask the underlying bootstrap result. The test also covers a partially existing organization to preserve idempotency.

## Manual Verification Bridge v1 before first push/merge

The repository materialization now includes a minimal repository-local Manual Verification Bridge in every planned SpanFabric repository. It provides a fixed review-subject SHA-256 algorithm, state/authority policy, standard-library validator, regression tests, minimal GitHub verification workflow, explicit `MANUAL_AUTHORITY` limitations and AGENTS rules. `verification/state.yaml` and `verification/reports/**` are the only fixed non-executable exclusions; policy, validator, tests, workflows, scripts and relevant configuration remain material and therefore invalidate prior review evidence.

The bridge is transitional: it does not pretend to replace the central Project Steward or prove external GitHub branch-protection/reviewer settings. Those remain explicit manual external tasks until centrally enforced.

Historical v1.2.0/v1.2.1/v1.2.2 attempts and findings remain immutable historical evidence. v1.2.3 requires a new Stage-A attempt and fresh pre-apply BREAKER before Stage B.
