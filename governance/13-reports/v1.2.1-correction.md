# v1.2.1 BuilderKit Correction

## Trigger
A sealed Phase-000 Stage-A attempt on Windows PowerShell 5.1 showed that v1.2.0 failed in the correct empty-organization state. With `$ErrorActionPreference = Stop`, the expected nonzero/stderr result from `gh repo view SpanFabric/platform` became a terminating `NativeCommandError`.

## Failure mechanism
Expected repository absence was encoded as native-command failure control flow. That is not portable across the supported Windows PowerShell execution semantics.

## Remediation
`bootstrap-repos.ps1` now executes one organization repository enumeration (`gh repo list ... --json name`), parses that state locally, and performs no expected-failure probe for absent repositories. Apply mode remains fail-closed on actual enumeration or create failures and preserves partial creation for explicit recovery.

## Regression protection
`11-bootstrap/tests/test_bootstrap_repos_contract.py` rejects reintroduction of `gh repo view` as the expected-absence probe, requires one-shot repository enumeration, and on Windows executes the dry-run with Windows PowerShell and a mocked authenticated empty organization. Success requires exit code 0 and all six exact planned creation actions.

## Evidence boundary
The previous failed v1.2.0 attempt remains historical evidence. It is not rewritten or promoted. Phase-000 Stage A must create a NEW sealed attempt against v1.2.1.
